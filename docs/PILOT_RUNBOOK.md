# Supervised pilot runbook

This checklist is a release gate, not a record that a real wedding has been run. A named professional/human coordinator must remain in charge. Never test uncommissioned software as the sole coordination channel at a wedding.

## Before accepting real data

Confirm purpose and access policy with the couple/coordinator. Identify the data owner, technical operator, event incident lead and manual backup channel. Use a separate cell and bot. Finish the P0 checks in ROADMAP.md; verify actual PostgreSQL, TLS, device, worker and integration behavior. Record provider/transcript retention and deletion arrangements.

## Setup and rehearsal

Create teams and locations, table capacities, guest list and family roster. Validate guest import previews and seating corrections. Create helpers, reuse guest identities where relevant, assign roles and issue personal invitations privately. Confirm identities out-of-band before distributing sensitive data. Import approved venue text with team visibility; do not upload full private contracts just to answer a simple venue question.

Enter a run sheet with explicit dependencies and fixed constraints. Give every task an owner, due time and location. Verify critical actual timings and vendor contacts by phone, not merely from stale documents. Create printed role briefs and a coordinator run sheet. Rehearse dinner delay, missing relative, late vendor, absent helper, provider outage and phone/network loss. The test wedding must contain fictional data.

Ensure every operator can open NOW, acknowledge a task, report an issue and contact the lead. Test older phones and shared Wi-Fi; the current demo's role picker is not onboarding. Activate reminders only after checking the clock, timezone, roster and schedule. Draft mode pauses new task reminders, not queued direct reports.

## Event-day operating rule

Helpers report observations, not inferred completion. Coordinator reviews consequence-bearing changes; targeted notices must be acknowledged, not merely marked sent. If a critical message is unacknowledged, use the agreed human channel. Do not wait for the agent in a safety emergency. Actual start/end cues are explicitly recorded; passing a scheduled time does not complete an activity.

If the model fails, keep using structured controls and the deterministic command vocabulary. If the application/network fails, the lead announces the manual fallback channel and one current master run sheet. Avoid simultaneous uncoordinated edits across paper/spreadsheets/app. Reconcile timestamped changes and ownership before restoring digital authority.

## Closeout

Resolve or hand off incidents, export an operational snapshot, back up the database under the agreed retention policy, revoke temporary helper access and archive the event. Archive is not deletion. Remove unnecessary PII/support exports/printed sheets according to policy, including provider records where applicable. Review missed/duplicate messages and wrong-person proposals without circulating guest details.

## Proposed pilot measures

Track coordinator interruption count, factual question response time, source-backed answer rate, report-to-decision and decision-to-acknowledgement latency, unacknowledged important changes, delivery failures, wrong-action proposals, permission denials and manual fallback success. Compare with a documented baseline or rehearsal, not retrospective guesses. Minimum safety targets are zero unauthorized writes/disclosures and explicit attribution for every consequential decision; these are acceptance targets, not achieved field results.
